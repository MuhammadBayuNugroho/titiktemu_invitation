# 30. PAYMENT FLOW

Flow:

```text
Customer clicks Pay
       ↓
POST /api/payments/create
       ↓
Server validates invitation
       ↓
Server retrieves plan
       ↓
Server retrieves price
       ↓
Server creates order
       ↓
Server creates Midtrans transaction
       ↓
Snap Token returned
       ↓
Frontend opens Midtrans
```

Browser hanya menerima data yang memang diperlukan untuk checkout.

Server key TIDAK BOLEH dikirim ke client.

---

# 31. PAYMENT VERIFICATION

Frontend callback hanya digunakan untuk UX.

Source of truth:

```text
Server Webhook
```

Endpoint:

```text
/api/webhooks/midtrans
```

Webhook harus:

```text
verify signature
verify order
verify amount
verify provider transaction
verify status
handle state transition
be idempotent
```

Jangan publish invitation hanya karena frontend mengatakan:

```text
payment success
```

---

# 32. IDEMPOTENCY

Webhook dapat dikirim lebih dari sekali.

Jika notification yang sama diterima dua kali:

```text
hasil akhir harus tetap satu transaksi valid
```

Jangan:

```text
duplicate order
duplicate payment
duplicate publish
```

Implementasikan idempotent processing.
